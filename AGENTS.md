# AGENTS.md

Tiny Vercel deployment (4 files, zero dependencies): a static chat UI in `public/` that calls a serverless proxy in `api/` which reverse-proxies to ChatGPT's unofficial Android backend API.

## Layout & entrypoints

- `api/chat.js` — Vercel serverless function (default `export`, `(req, res)`), the text-only backend entrypoint. Zero deps; `crypto` is the only import (builtin). Reads the user message from the **query param** `req.query.message` (GET request — not POST).
- `api/chat-image.js` — anonymous image upload endpoint. **POST only** (405 otherwise); accepts JSON body `{ message, images: [{ base64, mime, name, width, height }] }`. Runs a 3-step upload pipeline against **`backend-anon`** (NOT `backend-api` — that returns 401 on the finalize step): (1) POST `/backend-anon/files` to get `file_id` + `upload_url`, (2) binary PUT to `upload_url` with `x-ms-blob-type: BlockBlob` + `x-ms-version: 2020-04-08`, (3) POST `/backend-anon/files/process_upload_stream` with `{ file_id, use_case: 'multimodal', file_name, index_for_retrieval: 0 }` and wait for a `file.processing.completed` event in the JSON-lines response. Headers must include `OAI-Client-Type: android`, `OAI-Package-Name: com.openai.chatgpt`, `OAI-Device-Id` (UUID format), `X-OpenAI-No-Http-Logging`. Images then go into a `multimodal_text` payload with `image_asset_pointer` parts — **text part FIRST, then image pointers** — sent to **`backend-anon/f/conversation`** (NOT `backend-api`), which requires a prior anonymous token pipeline: `sentinel/chat-requirements` token → `f/conversation/prepare` conduit token → conversation with `openai-sentinel-chat-requirements-token` + `x-conduit-token` headers (verified reference: `chatgpt2api-cf`). **If upload fails, the error message names the exact failing step** (`[STEP-1 init]`, `[STEP-2 put]`, `[STEP-3 process]`, `[STEP-4 sentinel]`, `[STEP-5 prepare]`). **SSE parsing gotcha:** the anonymous endpoint returns top-level `message` snapshots (cumulative text), NOT the `data.v` patch arrays of the authenticated endpoint — the parser handles BOTH (A: top-level `message`, B: `data.v` patches, C: top-level append patches, D: `data.v.message`). Empty 200 responses surface as a diagnostic `"stream parsing failed"` error including raw bytes.
- `public/index.html` — entire frontend, plain HTML/CSS/JS, no build step. Runtime deps are CDN-loaded (`marked` for Markdown, `highlight.js` for code).
- `vercel.json` — routing: `/api/(.*)` → `/api/$1`, everything else → `/public/$1`. Sets `maxDuration: 30` on `api/chat-image.js` (uploads take longer than the 10s default). So the site is served from `public/` at `/`; any new page/asset must live under `public/`.

## Quirks to not miss

- **No package.json, no lockfile, no tests, no lint, no local dev command.** Deploy by pushing the folder to a git repo connected to Vercel (Vercel auto-detects it as a zero-config Node serverless function). There is no build step at all.
- **The backend is an undocumented hack, not a real API.** It fabricates Cloudflare cookies (`__cflb`, `__cfuvid`, `oai-sc`, `__cf_bm`), a device id, and a UUID-style `msgId` via `crypto.randomBytes()`, then POSTs a payload mimicking the ChatGPT Android app to `https://android.chat.openai.com/backend-api/f/conversation`. OpenAI can break this at any time; expect occasional 403s from Cloudflare against Vercel's IP (the code maps that to a canned "blocked" message).
- **Streaming is faked.** The payload sends `stream: true` / `force_use_sse: true`, but the function does one blocking `response.text()`, then manually walks SSE lines: keep lines starting `data:`, skip `[DONE]`, and append text from JSON `data.v` patches where `patch.p === '/message/content/parts/0'` and `patch.o === 'append'`. There is also a fallback that grabs `data.v.message.content.parts[0]` for assistant role when nothing was appended.
- **Response JSON shape:** always `{ "Owner -> ": "@black_fox_teach", "message": <echo of input>, "response": <text> }`. HTTP 400 when `message` is missing, 500 wrapped in `{ response: ... }` on backend errors.
- **Frontend data flow:** `sendMessage()` pipes `data.response` through `sanitizeAIResponse()` (strips OpenAI-injected UI junk like `{@body...}` and `<button block>`, wraps loose `<?php` blocks into fenced code) before `marked.parse()`. `addCodeBlockHeaders()` then injects a language label + copy button into every `pre` block — if you add rendering paths, keep this pipeline intact or code blocks will show raw `<button block>` HTML. Text-only messages go to `/api/chat?message=...`; when images are attached, the frontend base64-encodes them and POSTs to `/api/chat-image` instead (fallback to text-only endpoint if no image was readable).
- **Attachment UI:** the `+` button in the input picks files (max 4). Images get thumbnails in the preview bar and bubble; other files show name/size and only the file *name* is sent to the text endpoint (real non-image file analysis is not supported by this backend).
- **Comments and user-facing copy are in Bengali.** Preserve that style; do not "translate" or strip the Bengali comments.
- **This workspace runs on an Android device — no JDK/Gradle/SDK, no git repo here.** Do not attempt builds, installs, or `git` ops; verify by reading files only, and tell the user to build/deploy on their own machine.
